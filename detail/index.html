XSN:一支只增不減的計數器

RCSI DEEP-DIVE · 10 / 快照粒度
DB PLATFORM · PROD
READ-YOUR-OWN-WRITES + 語句級快照
同一個交易裡,讀得到什麼?
① 讀「自己剛寫的」
BEGIN TRAN
  UPDATE stock = 70我改,還沒 COMMIT
  SELECT stock → 70✓ 馬上讀,讀到自己的
COMMIT
先寫後讀,永遠讀得到自己的修改 —— 這是所有隔離級別的鐵則。RCSI 完全不影響這種寫法。
② 讀「別人剛提交的」
BEGIN TRAN
  SELECT stock快照#1→ 100
  ┄ 別人進貨 stock 100→130 並 COMMIT ┄
  SELECT stock快照#2→ 130
COMMIT
RCSI 每條語句重拍快照 → 第二次讀看得到別人中途的提交。(SNAPSHOT 交易級則整筆凍結、仍讀 100,還可能撞 error 3960。)
RCSI 只改變一件事:別人「未提交」的資料你讀不到(讀到舊值)。自己寫的、別人已提交的 —— 照樣讀得到。
read-your-own-writes 是 SQL 鐵則 · autocommit / ORM 先寫再查回 同樣不受影響 · 解 deadlock 用 RCSI、不需 SNAPSHOT 的 retry
