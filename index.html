鎖相容性矩陣
S + S✓同時讀,沒問題

X + X✗寫寫互卡,必等待

排隊還算小事。真正的災難,是兩個人「互相」等對方手上的鎖……

RCSI BRIEF · 04 / 解方
DB PLATFORM · PROD
SSMS — master
ALTER DATABASE [Production]
  SET READ_COMMITTED_SNAPSHOT ON
  WITH ROLLBACK IMMEDIATE;
Command(s) completed successfully.
讓讀的人,不再拿鎖。
0 行應用程式碼修改 資料庫層級,一次切換 這就是 RCSI
Read Committed Snapshot Isolation —— 從此,SELECT 不再和 DELETE 搶同一把鎖。

RCSI BRIEF · 06 / 效益
DB PLATFORM · PROD
"READERS DON'T BLOCK WRITERS. WRITERS DON'T BLOCK READERS."
開啟之後,我們得到什麼
讀不擋寫,寫不擋讀
報表、查詢、批次刪檔,同桌共存 —— 鎖等待從根本消失。
讀寫死結,直接絕種
SELECT 退出等待,環就接不起來 —— 是結構性消失,不是機率變低。
0 行程式碼修改
資料庫層一次切換,所有應用程式立即受益 —— 不用排開發人力。
把 NOLOCK 送進歷史
NOLOCK = 髒讀、跳列、重複讀;RCSI 只讀已提交資料,快又正確。
